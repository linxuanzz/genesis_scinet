> plan_local_repair这里选择哪种repair方法是不是可以直接用jev模型来做选择，而不是顺序走。

**可以。如果你说的 “jev 模型” 指 LLM，可以让它在** `plan_local_repair` **选择或排序修复方法，替代固定顺序。**

建议这样分工：

```
规则检查 → 筛出可行且有权限执行的动作
模型决策 → 根据故障、余量、剩余数据和 deadline 选择动作
代码执行 → 再检查容量、执行、验证结果；失败则回退或上报
```

例如，链路持续故障但备用路径可用，模型可以直接选择 `reroute`，不用先尝试 `extend → raise_rate`。

**模型负责策略选择，ledger 和执行代码负责约束与正确性。**它不能自行放宽 deadline、忽略容量，或执行未经授权的 borrow。

你当前已有 `RuntimePolicy` 接口，`RulePolicy` 是默认实现，结构上已经支持替换。但是否比按故障类型编写规则更有效，需要比较修复成功率、决策耗时和成本。

> jev的特点

**核心特征与工作方式**

**1. 三种输入原语（Primitives）**

Jev 在接收到一段上下文（State）和一个或多个问题（Questions）后，会跳过自回归逐字解码过程，并行输出经过校准的具类型答案。它仅支持三种输出原语：

- **Choice（多选一）**：从预设的枚举列表中选择一个最合适的选项，并给出每个候选分支的概率分布。
- **Score（数值评分）**：在有序离散区间（如 0 到 10 或自定义等级）内给出数值或量表评分。
- **Noul（二值布尔概率）**：回答类似“是否/是不是”的判断题，输出 0 到 1 之间的“是/真”概率值。 

**2. 核心优势**

- **速度极快**：端到端延迟通常在 **70ms 至 500ms** 之间，比传统大模型快 20 到 200 倍以上。
- **成本低廉**：输入价格极低（约为每百万 Token $0.042），且**输出 Token 永久免费**。
- **零幻觉与类型安全**：由于输出空间在调用前由 Schema（模式）严格限定，数学上不可能产生格式错误、越界或无效字符串。
- **诚实的校准概率**：基于 RLCD（面向校准决策的强化学习）训练，模型给出的置信度数值与真实命中率高度吻合（例如宣称 95% 把握时，实际正确率接近 95%）
