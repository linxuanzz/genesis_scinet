## 一 Network Agent 的运行时修复

这次讨论明确了四种修复动作的决策边界。**Network Agent 根据网络状态和预留账本计算可行方案。涉及推迟已承诺的完成时间或调整其他传输预留时，由 Scheduling Agent 根据任务依赖和优先级裁决。**

| 动作 | 会上提出的分工 |
| --- | --- |
| `extend` 延长预留 | Network Agent 计算可行的延长方案。Scheduling Agent 根据下游任务何时需要这份数据，决定最晚能延到什么时候。即使仍在原始 deadline 内，推迟已承诺的完成时间也可能影响下游。 |
| `raise_rate` 提高预留速率 | 有可用余量、能维持原有完成承诺且不挤占其他预留时，Network Agent 可以自行处理。 |
| `reroute` 改路由 | 备用路径容量足够、能维持原有完成承诺且不影响其他预留时，Network Agent 可以自行处理。 |
| `borrow` 借用低优先级流的带宽 | Network Agent 算出可行候选，给出受影响的 commitment ID、调整时段、新速率和预计完成时间。Scheduling Agent 结合优先级和任务依赖，选择一项或全部拒绝。 |

这套分工处于设计阶段，跨 agent 的审批接口和端到端行为仍待验证。 [11 月 9 日的修复边界讨论](20261109_runtime.md#五-本地修复策略kk-的问题与边界要求) · [同日 runtime 设计笔记](../notes/20261116_kksuggestionsinruntime.md)
